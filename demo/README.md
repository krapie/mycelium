# Demo recordings

Two kinds of scripted [VHS](https://github.com/charmbracelet/vhs) recording live here.

**Per-persona tutorial walkthroughs** (Software Engineer, Cloud Support Engineer, Solutions Architect — `src/tui/personas.js`), mocked/deterministic:

- `<persona>-highlight.tape` → a short (~20s) Organize → Learn → Reuse loop, sized for embedding directly in `README.md`.
- `<persona>-full.tape` → the complete 16-step tutorial, for YouTube.

**Flagship pitch video** (`pitch-en.tape` / `pitch-ko.tape`): why Mycelium exists, what it is, how to run it, then a live demo of the **full lifecycle** — organize, learn, reuse/context, knowledge review, merge, split, handoff to a different agent — against a richer 12-session/4-folder SWE-flavored dataset (`pitch-data.js`) than the per-persona tutorial uses. Mocked/deterministic like the persona tapes below (an earlier version used real LLM calls; see "The pitch video" section for why that changed), but with no tutorial narrator and its own dataset. See that section — its design differs enough from the persona tapes to warrant its own explanation.

Output lands in `demo/out/` (gitignored — not committed; regenerate locally or pull from the `demo-assets` GitHub Release).

## Regenerating

```sh
brew install vhs        # pulls in ttyd; ffmpeg comes along too if you don't have it
npm run record           # renders all six persona tapes into demo/out/
npm run record:pitch     # renders pitch-en.mp4 + pitch-ko.mp4 (mocked, ~40s each — see below)
```

Or render one at a time: `vhs demo/tapes/swe-highlight.tape` (run from the repo root — the tapes' `node src/cli.js ...` / `node demo/pitch-launch.js ...` are relative paths).

## Why it's built this way

**Safety first.** Every tape launches `node src/cli.js tui --tutorial` *directly*, never `mycelium demo`. The `demo` CLI command spawns a child with an isolated `MYCELIUM_HOME`, and on a **completed** tutorial run the *parent* (unmodified env) re-execs into your **real** `~/.mycelium` data in the same terminal — exactly what a recording must never show. The direct-invoke path has no parent watching for that handoff, so even a tape that runs all the way to the end and presses the final `q` (the `-full` tapes do) just exits cleanly back to the shell. Every tape also sets its own throwaway `MYCELIUM_HOME` under `/tmp` via VHS's `Env` command — never `~/.mycelium`, never `~/.mycelium-demo`.

**Wait on real text, not guessed timing.** `MYCELIUM_DEMO_MOCK_DELAY_MS` is set to 1200ms (vs. the real demo's 5000ms default) for reasonable pacing, but every step still uses VHS's `Wait+Screen@<timeout> /regex/` against the tutorial narrator's own `Step N/16` label (or a modal's real content) instead of a fixed `Sleep` — the same "poll for the real state, don't guess a delay" principle `test/e2e/demo-e2e.test.js`'s own `waitFor()` helper uses, so a render doesn't flake if a step happens to take longer than expected.

**Key sequences are proven, not invented.** `swe`/`cse`'s full sequences translate `test/e2e/demo-e2e.test.js`'s own working key-by-key sequences into VHS commands. `sa` has no e2e coverage — its down-navigation depth to `customers/nimbustech` was confirmed with a one-off interactive dry run against an isolated `/tmp` store before writing the tape, not guessed.

**Dimensions:** `Width 1600, Height 900, FontSize 15, Theme Dracula` — verified against a real render to not truncate/clip any panel content. `docs/tui.md`'s own manual-verification convention uses a much wider 220-column terminal specifically to rule out truncation bugs during testing; 1600px at this font size is narrower than that but was visually confirmed clean for recording purposes. If you change `FontSize`/`Width`, re-render `swe-highlight.tape` first and inspect a frame (`ffmpeg -i demo/out/swe-highlight.gif -vf "select=eq(n\,60)" -fps_mode vfr /tmp/check.png`) before re-rendering the rest.

## The pitch video

Deliberately built differently from the persona tapes above in two ways: no tutorial narrator (a promo shouldn't read as a product tour), and its own richer dataset (`pitch-data.js`, 12 sessions / 4 folders, shaped like `personas.js`'s storylines so it can share `tutorial-mock-llm.js`'s dispatch logic) rather than the 6-session persona set. Otherwise built the same way as the persona tapes now — mocked/deterministic, not real LLM calls.

**Why mocked, not real (this changed once already).** The first version of this video used real `claude`/`codex` calls, on the reasoning that authentic results matter more than repeatability for a one-off production. In practice that made organize alone (12 sessions, summarize + classify) take 110-150s+ per render — the large majority of a 3-minute video spent watching a progress bar — and made showing anything beyond organize+learn+reuse impractical, since every additional step would be its own real, slow, variable-timing LLM call. Switching to the same `__setTestProvider()` seam (`src/llm.js`) the persona tutorial already uses fixed both problems by construction: every classify/learn/knowledge/split call now resolves in ~1-2s (see `MYCELIUM_DEMO_MOCK_DELAY_MS` below), which is what made room to show the **full lifecycle** — organize, learn, reuse, knowledge review, merge, split — instead of just the first three, and dropped total render time from 140-200s+ to ~40s.

**`demo/pitch-launch.js` installs the mock provider itself, not the seed script.** `__setTestProvider()` is a module-level seam scoped to one process — `seed-pitch-demo.js` is a separate, short-lived process that exits before the tape ever presses a key, so setting it there would do nothing. `pitch-launch.js` builds `demo/pitch-data.js`'s storylines for the requested locale (`resolveStorylines()`, `src/tui/tutorial-mock-llm.js`) and calls `__setTestProvider(createMockProvider(...))` before mounting `sessionsView()`, so every key handler that calls `complete()` for the rest of that process's life hits the mock.

**Knowledge review (`k`) needs a folder active TODAY — pre-stage it instead.** `insight.js`'s `proposeKnowledgeRefreshes()` (the fresh-compute path `k` falls back to when nothing's queued) only considers folders with a session whose `startedAt` matches today exactly (`foldersActiveOn()`) — none of this video's sessions are dated today (they're all `daysAgo`-relative, for a realistic "been working on this a while" feel), so `k` would silently find nothing without help. `seed-pitch-demo.js` pre-stages a pending proposal for the merge-target folder via `writePendingKnowledgeText()`, the exact trick `src/tui/tutorial.js`'s `seedMockSessions()` already uses for the persona tutorial — `k` then hits the fast "reuse what's queued" path instantly instead of the date-gated one.

**Merge/split needs to land on the actual merged row, not just wherever focus was.** After `Shift+M` merges 2 of a folder's 3 sessions, blessed's list selection doesn't reliably track the new merged row by id — pressing `Shift+S` against whatever's merely *selected* can silently split the wrong (untouched) session instead. Fixed two ways: `pitch-data.js`'s untouched 3rd session in the merge-target folder is deliberately dated *older* than the merged product's inherited `startedAt` (see that file's own comment on `mergeSessions()`'s "earliest of the two originals" rule), so sorted most-recent-first the merged row always lands at the top of the folder's session list; the tape then sends 5 `Up`s (clamped at index 0, no wraparound) to land there deterministically regardless of where selection was left. Verified against real resulting state (`s.mergedFrom`/`s.splitFrom`, not just visually) via a one-off headless dry run using `test/tui-helpers.js`'s own `createTestApp()`/`sendKey()` harness — same method `test/e2e/demo-e2e.test.js` uses — before writing the actual tape, not guessed.

**Folder navigation depth is computed from `data.folders()`'s own sort, not guessed.** The Folders panel is a flat list — `Root`, `New`, then every folder path alphabetically, each real folder indented one level per path segment (confirmed by reading `sessions.js`'s `reloadFolders()`) — not a drill-down tree. For this dataset that puts `auth/token-refresh` at index 3 (`Root`, `New`, `auth`, `auth/token-refresh`), so 3 `Down`s from `Root` lands there; like the merge/split step above, this was confirmed via the same headless dry-run harness (checking `sessionsView`'s exposed `api.state.folder`), not assumed from the persona tapes' own down-count (which differs — their folder set is shaped differently).

**Safety — still the one rule that matters most, unchanged by the mock/real switch.** `demo/pitch-launch.js` mounts `sessionsView()` directly, deliberately skipping `runTui()`'s `startTuiRoutine()` call. That call runs a real `scanCycle()` immediately on startup, and adapters always read the actual `~/.claude`/`~/.codex`/`~/.kiro` history regardless of `MYCELIUM_HOME` — confirmed live that a normal launch against even a disposable `MYCELIUM_HOME` surfaced real personal session titles within seconds. Every command that touches the data layer (the seed script, the `mycelium()` shell function) must run under the tape's own `Env MYCELIUM_HOME` — **every single one**, no exceptions. An earlier version of `pitch-en.tape` set `MYCELIUM_HOME` only on the later `mycelium()` function definition, not on the seed command itself; the seed ran against the real `~/.mycelium` (`paths.js`'s own default) and wrote 12 fake sessions into it. Caught by checking the real store's session count before/after (AGENTS.md's own standing advice) and cleaned up with `scanner.js`'s real `deleteRaw()` on the exact 12 identified-by-content ids, then `reindex()` to drop the resulting stale index entries — not a raw `rm`. If you're editing these tapes, re-read this paragraph before touching the `Env`/seed lines.

**`seed-pitch-demo.js` is idempotent, not additive.** Each session gets a fresh `randomUUID()` — there's no stable id to overwrite by — so re-running it against a `MYCELIUM_HOME` that already has a prior run's data used to just pile up more sessions on top (found by hand: a second render of the same `/tmp` path ended up with 24 sessions instead of 12). Worse, clearing only the raw session files wasn't enough either — `TREE_DIR` (real folder directories, created by a previous run's `applyPlacements()`) survived that and left stale **empty** folders sitting alongside the real ones; a tape's alphabetical down-navigation landed on one of those by chance once, and pressing `w` found nothing to summarize, timing out waiting for a `KNOWLEDGE.md` draft that was never coming. The script now clears `RAW_DIR`/`TREE_DIR`/`DIGEST_DIR` up front, every run, so re-rendering against the same `/tmp` path is always a clean slate.

**The app must actually quit before the outro.** `mycelium` runs fullscreen (alternate-screen mode) for the entire live-demo section — everything typed after it launches goes to the app itself, not a shell. An earlier version of the outro skipped pressing `q`/`q` (the real quit-confirm, `app.js`'s `confirmQuit()`) before `Hide`-ing to `clear`/`cat` the outro banner; those became random keystrokes the still-running app mostly ignored, and the outro simply never appeared in the rendered output, with no error from VHS (the whole script "succeeded" — every command in the log ran, just against the wrong target).

**A typed-but-unsent line survives a `Hide`.** The how-to section types `npm install -g @kevinprk/mycelium` without pressing Enter (shown, never actually run, to avoid a real global install mid-recording) — a later `Hide`d `Type "clear"` used to append directly onto that same unsent input line instead of starting fresh, since nothing had submitted or cleared it first. Harmless in practice (it happens entirely inside `Hide`, and the following `Show`n `Type "mycelium"` + `Enter` still starts clean), but fixed properly with a `Ctrl+C` before the hidden `clear` rather than left as a latent gotcha.

**Wait markers must match the real locale's real UI text.** `suggestPlacements()`'s review-modal title, the context viewer's title, the knowledge-review modal title, the merge title prompt, and the split review modal title are all genuinely Korean when `config.json`'s locale is `ko` (`config.js`'s `contentLocale()` — see `AGENTS.md`) — `pitch-ko.tape` waits for `제안된 폴더 배치`/`컨텍스트 ·`/`지식 업데이트 검토`/`병합된 세션의 제목`/`분할 제안`, not the English strings. The generated `KNOWLEDGE.md`'s own `# <folder> — Project Knowledge` header stays English in **both** locales (`insight.js` never localized that one static wrapper line, deliberately out of scope for the locale work that made the prompts themselves follow it) — so that one Wait marker is identical in both tapes.

**Total render time and pacing.** Both tapes land around 125-126s end to end — comfortably under the 3-minute cap, no `Set PlaybackSpeed` needed (mocked calls don't have real-API timing variance to buffer against the way the earlier real-LLM version did). The holds after each `Wait+Screen` are deliberately sized to actually READ the screen (a 12-item placement list, a KNOWLEDGE.md draft, a review modal) — 5-6s for content-heavy screens, not the 1s "just satisfy the wait marker" holds an earlier cut used, which rendered in ~41s but was too fast for a human to follow. If you're retuning pacing, budget from the 180s cap backward rather than the wait markers forward — mocked calls are fast and deterministic, so total duration is almost entirely a function of the `Sleep` values you choose, not LLM timing.

**`MYCELIUM_DEMO_MOCK_DELAY_MS` is `5000`, not a short video-only value.** It's `tutorial-mock-llm.js`'s own real production default (what the persona tutorial/`mycelium demo` itself uses when nothing overrides it), reused here deliberately — an earlier cut set it to `1200` for speed, but a call resolving in ~1s next to real `claude`/`codex` latency (seconds to tens of seconds) read as suspiciously fast, like a corner had been cut, rather than a deliberate demo choice. Knowledge review (`k`) is the one step that stays genuinely instant regardless of this value — it reuses a proposal pre-staged at seed time (see below), which is correct, real behavior (a real daemon-queued review resolves instantly for the human too), not an inconsistency.

**Handoff (`h`) is the featured Reuse capability, not `n`.** The live demo ends by handing the one real, untouched session left in `auth/token-refresh` ("Fix duplicate refresh race near token expiry", originally `kiro`) to a **different** agent (`Claude Code`, first in the picker and not `kiro`) via `h` → "Copy command (new tab)" (never "Open here" — that would foreground a real interactive agent subprocess mid-recording, the same safety reasoning that already rules out `n`'s "open here"). Chosen over `n` (new session in a folder) because `h` directly answers the exact pain point the intro banner states ("Model boundaries — switch agents, lose everything"), and `launchAgent()`/`copyNewCommand()` (the shared code both `n` and `h` route through) already calls `injectAgentsMd()` whenever the session has a folder — so this one beat demonstrates both "hand off to a different agent" and "knowledge injected" at once, without `n` repeating the identical agent/directory/action-picker UI right after. The tape's own payoff: after quitting, it `cat`s the real `AGENTS.md` file the handoff just wrote into a fake project directory — concrete, on-disk proof the folder's knowledge was actually injected, not just a toast claiming it was.

**Real, existing (but fake) project directories, one per folder.** `seed-pitch-demo.js` sets every session's `cwd`/`projectDir` to a real `mkdirSync`'d directory under `` `${MYCELIUM_HOME}-repos/<folder-with-dashes>` `` (derived from `MYCELIUM_HOME`, no extra `Env` line needed) — this is what makes `n`/`h`'s directory picker (`reuse.js`'s `dirsForFolder()`) resolve automatically instead of falling back to a typed-path prompt, and what gives `injectAgentsMd()` somewhere real to write. Cleared and recreated every run, same idempotent-seeding reasoning as `RAW_DIR`/`TREE_DIR`/`DIGEST_DIR` — a stale `AGENTS.md` from a prior run would otherwise make the `cat`-the-proof beat show leftover content instead of a clean write.

**A real, pre-existing locale bug, found while building this beat — fixed, not routed around.** `src/handoff.js`'s `buildHandoff()` was entirely hardcoded Korean regardless of locale, missed by the earlier "locale-aware LLM prompts" work (which scoped to `learn.js`/`organize/classify.js`/`insight.js`/`split.js` only — `handoff.js` isn't itself an LLM prompt, it's a human-facing seed prompt for the *next* agent, but the same `contentLocale()` convention applies). Any English-locale user pressing `h` before this fix got an all-Korean prompt copied to their clipboard. Fixed the same way as the earlier prompts (Korean kept verbatim under a `'ko'` branch, English added alongside) — both because it was genuinely broken already, and because this tape now `cat`s real handoff-adjacent output (`AGENTS.md`) on camera, where a stray Korean line would have been a visible, on-brand embarrassment. `reuse.js`'s `injectAgentsMd()` had one smaller instance of the same thing (a hardcoded-Korean marker comment) — fixed identically.

## Hosting

GIFs/MP4s are **not** committed to git (keeps the repo/clone size lean) and are outside `package.json`'s `"files"` allowlist (`demo/` isn't listed, so `npm publish` never bundles them either). The persona recordings are uploaded as assets on a GitHub Release (`demo-assets`); `README.md`'s embedded GIF points at that release's stable download URL. `pitch-en.mp4`/`pitch-ko.mp4` are handed off locally for manual YouTube upload — not linked from `README.md` and not assumed to go on the same release unless asked.
